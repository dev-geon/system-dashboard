# 도형·관점 규칙 F1~F4

출처: Boardmix, 「순서도 기호 알아보기」 — 약속된 기호만 쓰기, 위→아래·왼→오른쪽, 기호 안에 처리 내용, 기호끼리 쉽게 구분, 단순하게, 같은 처리 반복 금지. 기호 의미는 플로우차트 표준(ISO 5807)의 기본 기호를 따른다.

| ID | 규칙 | 적용 | 판정 |
|---|---|---|---|
| F1 | 허용된 도형만 | 흐름도·구조도 | FAIL |
| F2 | 방향은 위→아래 또는 왼→오른쪽 | 흐름도·구조도 | FAIL |
| F3 | 분기는 출구 2개 이상, 출구마다 라벨 | 흐름도·구조도 | FAIL |
| F4 | 시작과 끝이 있다 | 흐름도(`flow`) | FAIL |

## F1 · 허용된 도형

| 기호 | 뜻 | Mermaid 표기 | 주로 쓰는 관점 |
|---|---|---|---|
| 단말 (둥근 끝) | 시작·끝 | `id(["주문 접수"])` | flow |
| 처리 (사각형) | 작업 하나 / 서비스·앱 | `id["재고 확인"]` | 전체 |
| 분기 (마름모) | 조건에 따라 갈림 | `id{"재고 있음?"}` | flow |
| 입출력 (평행사변형) | 데이터 입력·출력 | `id[/"주문서 입력"/]` | flow |
| 정해진 처리 (양옆 이중선) | 다른 곳에 정의된 처리 / 외부 시스템·큐·토픽 | `id[["결제 모듈"]]` | 전체 |
| 저장소 (원통) | DB·스토리지 | `id[("Orders Table · PostgreSQL")]` | 전체 |
| 준비 (육각형) | 초기화·설정 | `id{{"설정 로드"}}` | flow |
| 연결점 (원) | 다른 자리로 이어짐 | `id(("A"))` | flow |
| 문서 (물결 밑변) | 문서·리포트 산출물 | `id@{ shape: doc, label: "월간 리포트" }` | 전체 |

쓰지 않는 것: 둥근 사각형 `( )`, 깃발 `> ]`, 사다리꼴 `[/ \]`·`[\ /]`, 역평행사변형 `[\ \]`, 이중 원 `((( )))`, 위 표에 없는 `@{ shape: … }`. 비슷한 모양이 섞이면 기호끼리 구분이 안 된다.

라벨에 공백·괄호·특수문자가 들어가면 큰따옴표로 감싼다: `api["Order API · FastAPI"]`.

## F2 · 방향

`flowchart TB`(위→아래, `TD`도 같음) 또는 `flowchart LR`(왼→오른쪽)만. `BT`·`RL`은 읽는 방향과 반대라 쓰지 않는다.

고르는 기준: 단계가 길게 이어지면 `TB`, 계층(사용자 → 프런트 → API → DB)이면 `LR`. 단, **라벨이 길거나(`context` 수준의 한국어 라벨) 한 박스에서 여러 갈래로 퍼지면 `TB`** — `LR`은 폭이 금방 화면을 넘어 좁은 화면에서 첫 박스만 보인다.

## F3 · 분기

마름모에서 나가는 화살표가 2개 이상이고, 모두 라벨이 있어야 한다. 라벨 없는 분기는 어느 쪽이 "예"인지 알 수 없다.

```
chk{"재고 있음?"} -->|예| pay["결제"]
chk -->|아니오| wait(["입고 대기 안내"])
```

## F4 · 시작과 끝 (`flow` 관점만)

- 시작: 단말 `([ ])` 중 들어오는 화살표 없이 나가기만 하는 것 1개 이상
- 끝: 단말 중 나가는 화살표 없이 들어오기만 하는 것 1개 이상

## 구조도 도형 (`context` · `runtime` · `deploy`)

F1의 표는 **흐름도(순서도) 기호**다. 구조도는 "무엇이 있나"를 그리므로 기호 대신 C4식 구성요소 어휘를 쓴다 — 같은 Mermaid 괄호라도 구조도에서는 뜻이 다르다. 순서도 기호(분기·입출력·준비·연결점·문서)를 구조도에 쓰면 FAIL.

| 구성요소 | Mermaid 표기 | 화면 |
|---|---|---|
| 사람·행위자 | `id(["고객 · 웹 브라우저"])` | 사람 아이콘 카드 |
| 앱·서비스·도구 | `id["Order API · FastAPI"]` | 창 아이콘 카드 |
| 외부 시스템 (우리가 만들지 않은 것) | `id[["결제 대행 · PG사 API"]]` | 지구 아이콘 · 점선 카드 |
| 저장소 | `id[("Orders Table · PostgreSQL")]` | 원통 아이콘 카드 |
| 새로 넣거나 바꾸는 부분 | `class id1,id2 added` | 파란 카드 (AS IS ▶ TO BE 의 TO BE 색) |

- **계층은 `subgraph`로 나눈다(L4).** `subgraph users["사용자"] … end`. 화면은 계층을 **왼쪽→오른쪽 칸**으로, 나온 순서대로 놓는다 — 보통 사용자 → 에이전트·프런트 → 서버 → 저장소. 계층 밖 카드는 WARN
- **화면은 Mermaid가 아니라 빌더가 직접 그린다.** 카드는 아이콘(타입) + 굵은 이름 + 작은 타입 글자 — 라벨 `이름 · 타입`을 나눠 보여 준다. 소스 머리줄은 `flowchart LR`로 둔다(방향은 화면이 정한다)
- **선은 수평·수직 직선만.** 다른 칸이면 카드 옆 → 칸 사이 통로에서 직각으로 꺾어 → 대상 카드 옆, 같은 칸이면 위아래 수직선. 곡선은 쓰지 않는다
- **한 카드에서 나가는 선은 한 줄로 나가서 통로에서 대상마다 갈라진다.** 카드 하나에 나가는 선이 여러 개 생기지 않는다. 라벨은 갈라진 가지마다 대상 높이에
- 화살표는 **이웃한 칸끼리** 잇는다. 칸을 건너뛰면 선이 가운데 칸의 카드를 지나간다 — 그럴 땐 계층을 다시 나눈다
- 같은 칸 안에서 잇는 카드는 위아래로 붙여 둔다(소스에서 연달아 정의)
- 언제·어떤 조건에서 부르는지는 구조도 라벨에 쓰지 않는다. 그건 흐름도·시퀀스의 몫이다(D5)

## 관점 종류

| 종류 | 화면 이름 | 다이어그램 | 적용 규칙 | 담는 것 |
|---|---|---|---|---|
| `context` | 전체 맥락 | 계층 칸 + 카드 (좌→우) | D1~D8, 구조도 도형, L4 | 우리 시스템 하나 + 사용자 + 외부 시스템 |
| `runtime` | 실행 구조 | 계층 칸 + 카드 (좌→우) | D1~D8, 구조도 도형, L4 | 앱·서비스·DB·토픽과 호출 관계 |
| `deploy` | 배포 | 계층 칸 + 카드 (좌→우) | D1~D8, 구조도 도형, L4 | 무엇이 어디(컨테이너·함수·VM)에 떠 있나, CI 경로 |
| `sequence` | 시퀀스 | sequenceDiagram | D1·D2·D3·P1 | 한 기능의 요청·응답 왕복 |
| `flow` | 업무 흐름 | flowchart | D2~D4, F1~F4 | 업무 절차, 분기, 예외 경로 |

구조도에서 정적 파일 서빙과 API 호출을 섞지 않는다. 정적 웹 서버가 백엔드에 무언가를 "보내는" 화살표는 대부분 틀린 그림이다 — 브라우저가 정적 파일을 받고, 브라우저가 API를 호출한다.
