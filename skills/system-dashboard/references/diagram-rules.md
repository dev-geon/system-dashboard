# 다이어그램 규칙 D1~D9 · P1~P3 (D8 폐기)

출처: 박재홍, 「시스템 아키텍처 다이어그램, 아직도 이렇게 그리고 있다면 다시 생각해보자」(wikidocs, 2026-03-24) — Ilograph의 "아키텍처 다이어그램에서 흔히 저지르는 실수" 후속편과 HN 토론 정리.

`check_diagrams.py`가 이 표대로 판정한다. **FAIL은 빌드를 막고, WARN은 사람에게 보여 주고 남길지 묻는다.**

관점 종류는 두 계열이다. 규칙마다 어느 계열에 적용되는지 다르다.
- **구조도**: `context` · `runtime` · `deploy` — 무엇이 있고 무엇과 이어지나
- **흐름도**: `flow` — 일이 어떤 순서로 진행되나 (플로우차트 규칙 F1~F4는 `symbols.md`)
- **시퀀스**: `sequence` — 요청과 응답이 어떻게 오가나

## D1 · 라벨은 `이름 · 타입`

아이콘이나 라벨이 `DynamoDB`, `S3 Bucket`처럼 **타입만** 말하면 "이 테이블이 뭘 저장하는데?"에 답하지 못한다. 이름이 역할을 말하고, 타입이 기술을 말한다.

- 판정: 라벨에 ` · `(앞뒤 공백 있는 가운뎃점)이 있고 양쪽이 비어 있지 않아야 한다.
- 대상: 구조도의 처리 `[ ]` · 저장소 `[( )]` · 정해진 처리 `[[ ]]` · 입출력 `[/ /]` · 문서 박스. 시작·끝, 분기, 연결점은 제외. 시퀀스는 `participant x as 이름 · 타입`.

```
✗ db[("PostgreSQL")]
✓ db[("Orders Table · PostgreSQL")]
```

## D2 · 연결 없는 박스 금지

어디에도 이어지지 않은 박스는 "시스템의 일부"라는 것 말고 아무것도 알려 주지 않는다(예: 덩그러니 놓인 Route 53). 보통 한 장에 다 넣으려는 욕심에서 생긴다. 역할이 있다면 그 역할이 드러나는 관점으로 옮기고, 없다면 뺀다.

- 판정: 흐름도·구조도에서 들고 나는 화살표가 0개인 박스. 시퀀스에서 메시지를 주고받지 않는 참여자.

## D3 · 관점 하나에 박스 12개 이하

12개를 넘으면 레이아웃이 무너지고 한눈에 읽히지 않는다. 넘으면 관점을 쪼개거나 추상화 수준을 한 단계 올린다(`component` → `container`).

## D4 · 화살표는 뜻이 정해진 세 종류만

HN 토론에서 가장 많은 공감을 받은 지적: **화살표가 제어 흐름인지 데이터 흐름인지 합의하지 않는 것**. `A → B "고객 데이터"`는 "A가 요청한다"로도 "A가 보낸다"로도 읽힌다.

| 표기 | 뜻 | 화면 모양 |
|---|---|---|
| `-->` | 동기 요청 (호출하는 쪽 → 받는 쪽) | 실선 |
| `-.->` | 비동기 이벤트·메시지 발행 | 점선 |
| `==>` | 데이터 흐름 (복제·적재·배치) | 굵은 선 |

- FAIL: 머리 없는 선 `---` · `-.-` · `===` (방향도 뜻도 없다)
- WARN: 구조도에서 라벨 없는 화살표 — 무엇을 요청/발행하는지 `-->|주문 생성|`처럼 적는다
- WARN: 흐름도(`flow`)에서 `-->` 외 화살표 — 흐름도의 화살표는 진행 순서 하나뿐이다
- 범례는 빌드가 그 관점에서 실제로 쓴 화살표만 골라 자동으로 붙인다.

## D5 · 왕복 통신은 시퀀스로

A→B, B→C로 한 방향으로만 흐르게 그리면(컨베이어 벨트 증후군) 주니어나 비개발자는 그대로 믿는다. 실제로는 요청과 응답이 오간다. 그 왕복이 중요하면 `sequence` 관점으로 따로 그린다 — 시퀀스는 요청과 응답을 별도 화살표로 그려서 모호함이 없다.

- 판정: 구조도에 `<-->`가 있거나, 같은 두 박스 사이에 양쪽 방향 화살표가 다 있으면 WARN.
- **순번·조건은 구조도에 달지 않는다.** ①②③ 순번이나 "필요할 때만" 같은 조건을 구조도 화살표에 붙이면 모든 단계가 매번 일어나는 것처럼 읽히고 분기는 안 보인다. 구조도 라벨은 무엇을 부르는지만 쓰고, 언제·어떤 조건에서 부르는지는 `flow`(흐름도)로 따로 그려 분기와 예시 카드로 보여 준다. 검사기가 판정하지 않으므로 그리는 쪽이 챙긴다.

## D6 · 메시지 브로커는 토픽 단위로 (팬 트랩)

여러 서비스가 브로커 하나에 붙으면 "누가 누구에게 보내는지"가 브로커 박스에서 사라진다. 브로커 대신 **토픽(큐)을 박스로** 그려 개별 경로를 되살린다. 필요하면 브로커는 `subgraph`로 감싼다.

- 판정: 타입이 브로커(Kafka · RabbitMQ · SQS · SNS · Service Bus · Event Hubs · Pub/Sub · NATS · EventBridge · MQ)인데 이름에 `Topic` · `Queue` · `토픽` · `큐`가 없고, 연결이 3개 이상이면 WARN.

```
✗ bus[["Event Bus · Kafka"]]          ← 서비스 5개가 다 여기에 붙음
✓ t1[["order.created Topic · Kafka"]]  t2[["payment.done Topic · Kafka"]]
```

## D7 · 읽을 사람·추상화 수준 명시

청중을 모르면 추상화 수준을 정할 수 없다. 경영진에게 필요한 그림과 디버깅하는 개발자에게 필요한 그림은 다르다(C4 모델: Context · Container · Component · Code).

- 판정: 머리말에 `title` · `audience` · `level` · `repo` · `ref` · `asof`가 모두 있어야 한다. `level`은 `context` · `container` · `component` 중 하나.

## D8 · (폐기) 박스 → 코드 링크

0.2.0 부터 카드는 링크하지 않는다 — 카드를 누르면 GitHub 로 넘어가 읽던 화면을 잃는다는 피드백. 검사도 하지 않는다. 원본에 `click` 줄이 남아 있어도 P1 은 통과하고 화면에서는 무시된다.

## D9 · 구조도는 TO BE 한 장

바뀌는 작업의 구조도에 지금 쓰는 도구(AS IS)와 새 도구(TO BE)를 나란히 그리면, 둘이 같은 저장소·외부 시스템을 부르므로 같은 대상으로 선이 두 갈래씩 몰린다. 통로가 붐벼 선과 라벨이 겹치고, 읽는 사람은 "둘 다 계속 쓰나?"를 묻는다. 구조도는 **바뀐 뒤의 모습만** 그리고, 무엇이 왜 바뀌는지는 맨 위 AS IS ▶ TO BE 문장이 말한다.

- 판정: 같은 칸(subgraph)에 있는 기존 박스와 새 박스(`class … added`)가 같은 대상을 2곳 이상 함께 부르거나, 같은 대상을 부르면서 같은 출발점에서 함께 불리면 WARN.
- 고치기: 대체되어 사라질 쪽(AS IS)을 구조도에서 뺀다. 한동안 둘이 함께 돈다면(이중 운영) 그 사실은 예시 카드나 답변으로 알린다.

```
✗ bo["BackOffice 송신 · Python"] 와 hub["Data Hub · .NET"](added) 가 둘 다 KR API·LoggerData 를 부른다
✓ hub 만 그린다 — BackOffice 송신이 무엇이 문제였는지는 AS IS 문장에
```

## P1 · 검사기가 읽을 수 있는 문법만

검사를 결정적으로 하려고 Mermaid 문법의 일부만 쓴다. 이 밖의 문법은 FAIL로 알리고 고쳐 쓰게 한다.

- 흐름도: `flowchart TB|TD|LR` (또는 `graph`). 화살표 라벨은 `-->|라벨|`만 — `-- 라벨 -->` 형식은 쓰지 않는다
- 박스 ID는 영문·숫자·`_`·`-`. 같은 줄에 여러 문장을 `;`로 이어 써도 된다
- `subgraph` · `end` · `direction` · `classDef` · `class` · `style` · `linkStyle` · `click`(화면에서 무시) · `%%` 주석은 허용
- 화살표 ID 문법(`A e1@--> B`)은 쓰지 않는다
- 시퀀스: `sequenceDiagram` + `participant`/`actor` + `A->>B: 내용` 류 메시지 + `alt/opt/loop/par/else/end/Note/activate/deactivate/autonumber`

## P2 · 관점 형식

- 관점 제목은 `## view: <종류> | <화면 제목>`, 종류는 `context` · `runtime` · `sequence` · `flow` · `deploy`
- 관점마다 `mermaid` 코드 블록 정확히 1개
- 관점은 1~5개. 같은 종류를 두 번 쓰려면 `runtime-2`처럼 뒤에 `-숫자`를 붙인다

## P3 · 애니메이션 금지

움직이는 화살표는 방향을 반복할 뿐 정보를 더하지 않는다. `animate`가 소스에 있으면 FAIL.
